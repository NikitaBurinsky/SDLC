### 2. По замечанию №2: Уточнение формулы расчета рецептов (уварка vs разваривание)
- **Статус:** ✅ **ПРИНЯТО (с математическим доказательством инвариантности)**.
- **Обоснование:** Закон сохранения энергии гарантирует, что термическая обработка меняет лишь массу воды (которая имеет 0 ккал), а суммарная калорийность ингредиентов $\sum K_{сыр}$ остается неизменной.
- **Математическая модель в `REQ-FUNC-003`:**
  $$K_{100г} = \frac{\sum_{i=1}^n K_{сыр, i}}{M_{готового\_блюда}} \times 100$$
  - **Случай 1 (Уварка/ужарка мяса):** $M_{гот} < M_{сыр}$ $\Rightarrow$ знаменатель уменьшается, удельная калорийность $K_{100г}$ возрастает.
  - **Случай 2 (Разваривание каши/макарон):** $M_{гот} > M_{сыр}$ $\Rightarrow$ знаменатель увеличивается за счет воды, удельная калорийность $K_{100г}$ уменьшается.
  Формула абсолютно инвариантна и точна для обоих процессов! Пояснение внесено в раздел 3.2 спецификации SRS.

### 3. По замечанию №3: Кэширование запросов к Open Food Facts API
- **Статус:** ✅ **ПРИНЯТО В РЕАЛИЗАЦИЮ**.
- **Обоснование:** Публичный API действительно имеет лимиты частоты запросов (rate limits), и прямой поиск без кэша привел бы к ошибкам HTTP 429.
- **Внесенные изменения:**
  - В требования внешних интерфейсов **`REQ-INT-001`** и надежности **`REQ-REL-002`** заложена архитектура двухуровневого поиска:
    1. Первичный опрос локальной базы данных PostgreSQL (индекс по названию и штрихкоду).
    2. Обращение к внешнему REST API Open Food Facts только при промахе кэша.
    3. Автоматическое сохранение найденных записей в локальную СУБД.

---

### 4. По замечанию №4: Сканирование порции по 2D-фотографии камерой смартфона
- **Статус:** ❌ **АРГУМЕНТИРОВАННО ОТКЛОНЕНО**.
- **Технико-экономическое обоснование отклонения:**
  1. **Недопустимая погрешность:** По плоской 2D-фотографии без аппаратного LiDAR-сканера или калибровочных меток невозможно достоверно определить глубину посуды, плотность продукта и скрытое масло. Погрешность оценки объема превышает 35–50%, что недопустимо для диетического трекера.
  2. **Превышение бюджета:** Аренда GPU-инфраструктуры для инференса тяжелых моделей сегментации (типа Mask R-CNN) приведет к кратному росту TCO (совокупной стоимости владения), что не укладывается в рамки учебного проекта.
  3. **Альтернативное решение:** Для первого релиза утвержден надежный ввод точной массы с кухонных весов либо выбор стандартных порций (1 шт, порция 200г, столовая ложка).
