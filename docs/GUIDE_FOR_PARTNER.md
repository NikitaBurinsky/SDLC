## 🎯 В чем твоя задача по методичке?
По условиям лабораторной работы №3 студенты работают в парах: один играет роль **Менеджера проекта**, а второй — **Заказчика**.
1. Никита разработал спецификацию требований к системе (SRS v0.2), диаграммы SysML v2 и мокапы интерфейса.
2. Ты как Заказчик знакомишься с проектом и **оформляешь свои требования/пожелания в виде Pull Request (PR)**.
3. В твоем PR выдвигаются 4 конкретных замечания (3 конструктивных и 1 заведомо невыполнимое), которые Никита анализирует, принимает конструктивные в отчет и аргументированно отклоняет невыполнимое.

## 🚀 Как подготовить PR (выбери самый удобный способ):

### Вариант 1: Автоматически через скрипт (Рекомендуется — в 1 команду!)

1. Открой терминал в корне проекта (репозитория).
2. Выполни скрипт:
   * **Windows (PowerShell):**
     ```powershell
     powershell -ExecutionPolicy Bypass -File .\apply_partner_pr.ps1
     ```
   * **Linux / macOS / Git Bash:**
     ```bash
     bash apply_partner_pr.sh
     ```
3. Скрипт сам создаст ветку `customer-feedback`, добавит файл `srs/customer-feedback.md` и сделает коммит.
4. Отправь ветку на GitHub:
   ```bash
   git push -u origin customer-feedback
   ```
5. Перейди по ссылке в терминале на GitHub и нажми **«Compare & pull request»**!

---

### Вариант 2: Через готовый патч-файл (`customer_feedback.patch`)

Если ты предпочитаешь чистый Git:
```bash
# 1. Перейди на ветку lab3 (или main)
git checkout lab3

# 2. Создай изолированную ветку для ревью
git checkout -b customer-feedback

# 3. Примени патч
git apply customer_feedback.patch

# 4. Закоммить и запушь
git add srs/customer-feedback.md
git commit -m "docs(review): add customer wishes and feedback for NutriTrack SRS"
git push -u origin customer-feedback
```

---

### Вариант 3: Полностью через браузер на GitHub (без консоли)

1. Открой репозиторий проекта на GitHub.
2. Переключись на ветку `lab3`.
3. В выпадающем списке веток введи название новой ветки: `customer-feedback` и нажми **Create branch**.
4. Нажми **Add file ➡️ Create new file**.
5. Имя файла: `srs/customer-feedback.md`.
6. Скопируй и вставь текст из файла `customer-feedback.md`.
7. Внизу нажми зеленый **Commit changes...**.
8. GitHub сразу предложит желтую плашку **«Compare & pull request»** — нажми её!

## 📝 Что написать в GitHub Pull Request (готовый шаблон):

### Заголовок PR (Title):
```text
[Customer Review] Замечания и предложения Заказчика к спецификации NutriTrack SRS
```

### Описание PR (Description / Body):
Скопируй и вставь этот текст:
```markdown
## Замечания и предложения от бизнес-сообщества (Заказчика)

В рамках лабораторной работы №3 проведена экспертиза требований к веб-приложению «NutriTrack». 
Предлагаются следующие дополнения и уточнения к спецификации требований:

1. **[REQ-WISH-01] Трекер суточного потребления воды (Гидробаланс):**
   Добавить учет гидратации с расчетом нормы (30 мл на 1 кг) и виджетом быстрых отметок стаканов по 250 мл на дашборде.
2. **[REQ-WISH-02] Алгоритм расчета уварки/ужарки для сложных рецептов:**
   Уточнить математическую модель калькулятора составных блюд при противоположных процессах: уварке/ужарке мяса (уменьшение массы) и разваривании круп (увеличение массы).
3. **[REQ-WISH-03] Кэширование запросов Open Food Facts API:**
   Внедрить локальное кэширование в PostgreSQL для защиты от ограничений частоты запросов (rate limits) внешнего API.
4. **[REQ-WISH-04] Определение веса порции по фото камерой смартфона:**
   Предлагается внедрить функцию автоматического сканирования блюда нейросетью без кухонных весов.

Прошу Менеджера проекта рассмотреть предложения, предоставить техническое обоснование и обновить спецификацию SRS.
```

## 💬 Как оставить комментарии в PR (если препод просит показать ревью):
В интерфейсе PR перейди на вкладку **Files changed** (`srs/srs-nutritrack.md`) и нажми синий плюсик на строках требований, чтобы оставить замечания:

1. **К разделу 2.2 / REQ-FUNC-002 (Дневник):**
   > *«Одного учета калорий мало для контроля метаболизма. Нужен трекер воды с отображением стаканов по 250 мл!»*
2. **К разделу REQ-FUNC-003 (Калькулятор рецептов):**
   > *«А если я варю кашу, крупа разваривается и увеличивается в весе, а мясо уваривается. Ваша формула точно посчитает оба случая?»*
3. **К разделу 3.1.3 (Open Food Facts API):**
   > *«У публичного API есть лимиты на число запросов в секунду. Сервер нас не заблокирует при массовом поиске?»*
4. **К разделу 3.6 (AI/ML):**
   > *«Хочу, чтобы пользователь фоткал тарелку на телефон, а система сама определяла точный вес каждого куска с точностью до грамма!»*
